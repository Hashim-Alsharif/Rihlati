## الأدلة التقنية الحالية

- 104 اختبارات Python محلية ناجحة، على SQLite مؤقتة وبمزودات صوت/ذكاء بديلة؛ على Linux نُفذت 104 حالات، نجحت 103 وتُخطيت واحدة خاصة بالمنصة. 8 اختبارات خاصة بالتطبيق ناجحة، وفحوص JavaScript للواجهة ودليل المستخدمين والمسار والمراجعة ناجحة.
- بناء Android Debug ناجح. لا توجد IPA مبنية أو اختبارات iOS فعلية أو شهادة توقيع متجر.
- فحص واجهة التطبيق بعروض 320 و390 و768 و1024 و1366؛ نجاح تسجيل عضو تجريبي وفتح PDF والتحويل لتذكرة عند غياب المصدر.
- فصل جلسات الويب والتطبيق، اختبار منع الأدمن في التطبيق، حماية CSRF وعزل المكاتب واختبار منع عرض ملفات المشروع الخاصة.
- فحص npm لحزم التطبيق وفحص pip-audit لاعتماديات Python المقفلة لم يبلغا عن ثغرات معروفة بعد تحديث الاعتماديات وقت النشر. لا يعادل ذلك فحصًا أمنيًا مستقلاً أو ضمان انعدام الثغرات.
- نسخ SQLite احتياطيًا قبل تحديث تشغيل الخادم؛ لم تُحذف أو يُعاد بناء قاعدة التشغيل.

## مراجعة المكتبة

فحص قراءة فقط لقاعدة التشغيل عند النشر: 69 مرجعًا، منها 68 بحالة approved وواحد pending_review، و2708 صفحات و5599 مقطعًا. هذه أرقام الفهرسة لا مقاييس دقة الإجابة. المصدر قيد المراجعة لا يستخدم لمجرد وجوده ضمن حزمة المكتبة.

تصنيف المراجع الحالي: 24 عربية، و7 إنجليزية، و18 فلبينية/تغالوغ (`fil` و`tl`)، و5 فرنسية، و10 أمهرية، و5 سواحيلية. وجود المرجع أو دعم الواجهة لا يثبت اكتمال النص المستخرج أو صحة OCR أو جودة الإجابة والصوت بتلك اللغة. يعامل مرشح اللغة `tl` و`fil` كبديلين، دون خلطهما باللغات الأخرى. اعتماد status في القاعدة لا يغني عن توثيق اسم المراجع والطبعة والحقوق، والمراجعة البشرية.

## الأولويات المتبقية قبل اعتماد تجربة التحكيم

1. استخدام حسابات اختبار مخصصة للمحكمين وعدم مشاركة حساب الإدارة الرئيسي. نُقلت البيانات الحالية إلى السيرفر بطلب المالك، ولم تُنشر في GitHub. لا تعرض بيانات المستفيدين في الفيديو أو العرض.
2. استكمال فحص المصدر والصفحة ونتائج OCR وتغطية اللغات، ثم إعداد مجموعة أسئلة موثقة مع مختصين. نقيس صحة الاستشهاد والامتناع عند نقص الدليل وزمن الرد وجودة الصوت، ولا نخترع نسب نجاح.
3. اختبار الهاتف على Android وiPhone وiPad فعليًا: جلسة HTTPS، التقاط الصوت، تشغيل الصوت، رفع مرجع، قراءة PDF، انتهاء الجلسة، صلاحيات المكتب، العودة من الخلفية، الاتجاهين وحجوم الخط.
4. استكمال النسخ المشفرة خارج السيرفر والمراقبة والاحتفاظ وحدود الإنفاق واختبار التزامن والذاكرة وOCR. HTTPS والخدمة والجدار والنسخ اليومية المحلية مفعلة، ونجح اختبار استعادة لقطة SQLite في قاعدة منفصلة. لا يُفتح تشغيل loopback المحلي مباشرة للإنترنت.
5. اعتماد الخصوصية والاحتفاظ والحذف وموافقة المستخدم على معالجة نصه وصوته لدى المزود، وتحديد من يتلقى التذاكر ومتى. إرسال البريد وSMS واستعادة الحساب الذاتية تحتاج مزودًا منفصلًا.
6. فحص مستقل للأمان والصلاحيات ورفع الملفات، واستمرار فحص الحزم والأسرار قبل التحديثات. النسخة العامة منشورة بلا قاعدة خاصة أو كلمات مرور أو مفاتيح توقيع، مع إذن نشر المكتبة من صاحب المشروع.
7. تحديث العرض وتسجيل الفيديو ثم تجربة التحكيم من شبكة وجهاز غير جهاز التطوير. تعيين مسؤول للرد والدعم طوال الشهرين وآلية تعافٍ إذا تعطل المزود.

## بوابة القبول العملية

نجاح تسجيل عضو ثم ربطه بمكتب معتمد، وحفظ تقدمه بين الويب والتطبيق؛ جواب بمصدر صحيح؛ سؤال لا دليل له يصعد؛ طلب مختص بعد جواب يصعد أيضًا؛ رد المكتب يظهر للمستفيد؛ مكتب آخر لا يرى التذكرة؛ مرجع جديد لا يستخدم قبل اعتماده؛ تصحيح لا يعمم قبل المراجعة؛ حساب أدمن مرفوض في التطبيق ويعمل على الويب؛ نسخة احتياطية تستعاد على بيئة منفصلة؛ لا أسرار في ملفات النشر. كل بند يحتاج نتيجة وتاريخًا ومنفذًا عند اختبار البيئة المنشورة.
