# تشغيل ونقل رِحلتي

نُشرت نسخة التجربة والتحكيم يوم 5 أكتوبر 2026 على [rihlati.me](https://rihlati.me/) و[تجربة التطبيق](https://rihlati.me/app/). جميع مسارات المشروع هنا نسبية إلى جذر `Rihlati`، إلا مسارات النظام في دليل السيرفر. لا يساوي النشر اعتمادًا أمنيًا أو شرعيًا أو نجاح جميع سيناريوهات القبول.

إعداد Ubuntu / Caddy / systemd والفصل بين الكود والبيانات في `../deploy/README.md`؛ طُبقت على السيرفر. نسخة الكود والمكتبة العامة على [GitHub](https://github.com/Hashim-Alsharif/Rihlati)، والبيانات الخاصة على السيرفر فقط ولم تدخل المستودع العام.

## سجل تحقق النشر — 5 أكتوبر 2026

- Ubuntu 24.04، Python 3.12، Node.js 22، Caddy وWaitress خلف HTTPS. خدمة `rihlati` تعمل بحساب غير إداري وعلى loopback فقط؛ المنافذ العامة المسموحة 22 و80 و443. لم تُغيّر بيانات دخول SSH.
- نُقلت لقطة SQLite متسقة والكتب والصور وملفات OCR والإعدادات الخاصة، مع بقاء الأصل المحلي. تطابقت أعداد السجلات والملفات وبصمات حزمة النقل. لا تبدأ استخدامًا متوازيًا للقاعدة المحلية والسيرفر: التغييرات اللاحقة لا تتزامن تلقائيًا؛ السيرفر هو نسخة التشغيل المشتركة الآن.
- A للاسم الرئيسي وwww يشيران للسيرفر، وأزيل توجيه IPv6 القديم وربط خدمة الموقع السابقة بموافقة المالك. لم تتغير سجلات البريد ولم يُلغَ اشتراك.
- صدرت شهادتا Let's Encrypt للاسمين؛ فُحص TLS من خارج السيرفر دون تعطيل التحقق من الشهادة. HTTP يحوّل إلى HTTPS وwww يحوّل إلى الاسم الرئيسي مع حفظ المسار. التجديد مُدار تلقائيًا بواسطة Caddy؛ لا يعني ذلك وجود مراقبة خارجية للتجديد.
- `/api/health` وواجهة الويب و`/app/` تستجيب بنجاح. فُحصت شاشتا الدخول في المتصفح دون أخطاء JavaScript مسجلة أثناء التحميل. فحص خارجي أثبت 401 للمسارات المحمية دون دخول، و403 للإدارة عبر `/app-api/`، و404 لعناوين ملفات الأسرار وقاعدة البيانات والكود وGit.
- فُحصت جلسات زائر مستقلة للويب والتطبيق مع Secure وHttpOnly وSameSite=Lax وHSTS، ورفض POST بلا CSRF. لا يعوض ذلك اختبار قبول كامل لحسابات أعضاء ومكاتب وأدمن على الموقع المنشور.
- اختبارات Python المحلية: 104 ناجحة؛ على Linux: 104 حالة، نجحت 103 وتُخطيت واحدة خاصة بالمنصة. اختبارات التطبيق الثمانية وبناؤه نجحا على Linux؛ فحص الاعتماديات بـnpm audit وبـpip-audit للملف المقفل لم يجد ثغرات معروفة وقت الفحص. لا يساوي فحص اختراق مستقلًا.
- نُفذت خدمة النسخ الاحتياطي، ثم نُسخت اللقطة إلى قاعدة مؤقتة منفصلة: `integrity_check=ok` وتطابقت أعداد الجداول المفحوصة. مؤقت النسخ اليومية مفعّل؛ النسخ على السيرفر فقط، وتحتاج خطة حفظ خارجية مشفرة واحتفاظ محدد.
- لم تُنفذ استدعاءات AI أو تحويل صوت مدفوعة ضمن فحص النشر هذا، ولم يُختبر ميكروفون أو أجهزة iOS فعلية. تجربة `/app/` ليست إصدار متجر؛ يلزم بناء وتوقيع واختبار التطبيقات المثبتة على الدومين.

## جهاز التطوير وGitHub

شغّل `Start-Rihlati.cmd` على Windows أو `python scripts/api_server.py` داخل البيئة الافتراضية. الخادم على `127.0.0.1:8080`. نقطة `/api/health` لا تنشئ مستخدمًا ولا تستدعي خدمة مدفوعة. سجلات المشغّل في `data/logs/`.

جذر المستودع المقترح يحتوي `Rihlati/` و`rihlatiApp/` معًا. افتحه في VS Code، وراجع قائمة الملفات المرشحة؛ بقية ملفات صاحب المشروع في المجلد الأب ليست للنشر. استثناءات Git الخارجية والمحلية لا تغني عن الفحص. قاعدة SQLite والكتب والصور الخاصة والسجلات و`.venv` و`node_modules` و`.enviroment.local` لا تدخل Git. ignore لا يعالج سرًا سبق رفعه؛ عند التسريب يجب تدوير المفتاح وتنظيف التاريخ. تحقق من حقوق توزيع الكتب.

لا تستخدم خادم HTML منفصلًا أو `flask run --debug` للنشر. إذا كان المنفذ مشغولًا، حدد العملية المالكة قبل إيقافها؛ لا توقف عمليات Python عشوائيًا.

## تجهيز خادم جديد

ابنِ واجهة التطبيق من `rihlatiApp` بالأمرين `npm ci` ثم `npm run build` قبل تشغيل الويب. تبقى `rihlatiApp/www` شقيقة `Rihlati`، ويعرضها الخادم على `/app/` بقائمة سماح ثابتة. لا يحتاج التطبيق قاعدة ثانية. تطبيق الهاتف المثبت يحتاج بناءً جديدًا مع `RIHLATI_API_ORIGIN=https://YOUR-DOMAIN` ثم `npm run sync`؛ لا تستخدم إعداد loopback التجريبي في نسخة التحكيم الموزعة.

1. حساب خدمة غير إداري ونظام محدث وقرص مشفر. لا تجعل جذر المشروع مجلد static عامًا؛ فقط مسارات التطبيق المسموحة تُعرض.
2. انقل الكود وأنشئ `.venv` وثبت `requirements.txt`. لا تنقل البيئة الافتراضية بين أنظمة مختلفة.
3. انقل `data/` و`references/` من نسخة متسقة عبر قناة آمنة. انقل الأسرار منفصلة، خارج سجلات CI وصور الحاويات.
4. احصر صلاحية `.enviroment.local` بحساب الخدمة. على Linux مثلًا `chmod 600 .enviroment.local`؛ على Windows راجع ACL. الملف نص خاص وليس تشفيرًا مستقلًا.
5. لقاعدة جديدة شغّل `python scripts/setup_admin.py`. عند نقل القاعدة الحالية لا تعِد إنشاء الأدمن. أضف البريد والجوال وغيّر كلمة البداية محليًا. وضع الإنتاج يرفض العمل قبل ذلك.
6. اضبط `RIHLATI_ENV=production` و`PUBLIC_URL=https://YOUR-DOMAIN` في ملف الإعدادات. أبقِ `RIHLATI_HOST=127.0.0.1` عند وجود الوكيل العكسي على الخادم نفسه.
7. ضع Caddy أو Nginx أمام Waitress بشهادة HTTPS صالحة، وحافظ على Host الخاص بالدومين. وجّه إلى `127.0.0.1:8080` ولا تعرض 8080 مباشرة للإنترنت. اضبط حد الرفع والمهلات وتحديد المعدل في الوكيل.
8. الإنتاج يستخدم Secure وHttpOnly وSameSite=Lax وHSTS. التطبيق لا يثق تلقائيًا في `X-Forwarded-For`؛ لا تفعّل ثقة عامة بالوكلاء. عنوان العميل الحقيقي يحتاج ضبط الوكيل الموثوق بعينه ثم اختبار تحديد المعدل.
9. شغّل كخدمة مع إعادة تشغيل ومراقبة ونسخ احتياطي. لا تسجل كلمات المرور أو المفتاح أو نصوصًا حساسة. الخدمة والنسخ المحلية اليومية مفعّلان في نسخة التحكيم؛ المراقبة الخارجية والنسخ خارج السيرفر لم تُجهزا بعد.
10. اختبر من الدومين: التسجيل، اعتماد المكتب، العزل، تغيير كلمة المرور، الرفع، التذاكر، الصوت، والنسخ الاحتياطي والاستعادة على نسخة منفصلة.

SQLite مناسب لخادم واحد بحمل محدود، وليس ملفًا مشتركًا بين خوادم أو على نظام ملفات شبكي. التوسع المؤسسي يحتاج تقييم PostgreSQL وطابور مستقل وبحث دلالي وتخزين ملفات خاص. إضافة الحسابات لا تنفذ هذه التقنيات تلقائيًا.

## OCR

النص الرقمي يُستخرج بـpypdf. OCR العربي اختياري: Node.js وحزمة `tesseract.js` في `package.json` وأداة `pdftoppm` من Poppler وملف `ara.traineddata` في `data/ocr/lang/`. ثبت حزمة Node بالإصدارات المقفلة عبر `npm ci --ignore-scripts`؛ يمكن ضبط `RIHLATI_PDFTOPPM` لمسار الأداة. حزم بيئة المطور fallback محلي فقط وليست متطلبًا لمسار جهاز بعينه.

الكتب المصورة بلغات أخرى تحتاج حزمة OCR واختبارًا إضافيًا. المرجع بلا نص صالح يبقى للمراجعة. الفهرسة بخيطين وقائمة انتظار 8 وظائف؛ عند توقف الخادم قد تحتاج إعادة طلب الفهرسة. لا يوجد طابور موزع دائم.

## النسخ الاحتياطي

`python scripts/backup_data.py` ينشئ نسخة SQLite مؤرخة لا يستبدل نسخة سابقة. احفظ معها الكتب والصور والإعدادات وملف الأسرار المشفر خارجيًا. عند الاستعادة أوقف الخادم المحدد، احتفظ بالحالة الحالية، واختبر الاستعادة في مجلد منفصل أولًا. لا تعِد بناء القاعدة ولا تنقل قاعدة الاختبار 8081 إلى التشغيل الفعلي.

## ما يلزم قبل الإطلاق العام

- مراقبة التشغيل والشهادات، نسخ مشفرة خارج السيرفر، وسياسة احتفاظ واختبار حمل؛ الدومين وTLS والخدمة والنسخ المحلية قائمة في نسخة التحكيم.
- مزوّد بريد/SMS للتحقق والاستعادة؛ المتاح الآن إجراء إداري بعد تحقق بشري.
- سياسة خصوصية واحتفاظ بالبيانات وموافقة المستفيد على معالجة الأسئلة والصوت.
- تدقيق شرعي ولغوي، تقييم للمساعد، وفحص اختراق مستقل؛ انظر `SECURITY.md`.
- سقف إنفاق وتنبيهات في حساب OpenAI، وتجربة الصوت على الأجهزة واللغات المستهدفة.
