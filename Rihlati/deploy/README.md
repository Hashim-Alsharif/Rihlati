# نشر رحلتي للتحكيم — Ubuntu 24.04

طُبقت هذه الإعدادات على خادم التحكيم يوم 5 أكتوبر 2026، وفُحص الموقع على `https://rihlati.me` وتجربة التطبيق على `/app/`. لا تمثل اعتمادًا أمنيًا. لا تعرض التشغيل المحلي مباشرة للإنترنت. سجل التحقق وحدوده في `../docs/DEPLOYMENT.md`.

## فصل الكود عن البيانات

المستودع في `/opt/rihlati` وبداخله `Rihlati` و`rihlatiApp`. الكود والبيئة الافتراضية مملوكان لمسؤول النشر وغير قابلين للكتابة من مستخدم الخدمة `rihlati`. جهّز `Rihlati/data` و`Rihlati/references` بأذونات خاصة وملكية مستخدم الخدمة؛ هما مجلدا الكتابة الوحيدان.

ضع الأسرار في `Rihlati/data/private/.enviroment.local` بأذونات `600`. ملف الخدمة يحدد مكانه عبر `RIHLATI_ENV_FILE`؛ تبقى واجهة الإدارة قادرة على تحديث المفتاح. لا تضع أسرارًا في Git أو أوامر الطرفية أو ملفات الخدمة أو بناء التطبيق. لا تنسخ `.venv` أو `node_modules` من Windows إلى Linux.

## خطوات التشغيل

1. افحص نظام السيرفر والمنافذ والخدمات والمساحة قبل أي تعديل. لا تغير SSH أو الجدار الناري دون وسيلة رجوع. افتح 80/443 للويب وأبقِ 8080 محليًا.
2. ابنِ Python 3.12 venv من `Rihlati/requirements.txt`. جهّز Node.js 22 أو أحدث متوافق، وثبّت اعتماديات المجلدين. داخل `rihlatiApp` استخدم `npm ci` ثم `npm run build` دون `RIHLATI_API_ORIGIN` لبناء تجربة المتصفح على نفس الدومين. هذا ليس إصدار متجر.
3. انقل SQLite بلقطة متسقة من `scripts/backup_data.py`، لا بنسخ ملف قاعدة مستخدمة مباشرة. لا تستبدل قاعدة قائمة على السيرفر، ولا تشغّل إعادة بناء المعرفة. حافظ على المسارات النسبية للكتب والصور وملفات OCR والمراجعات. أبقِ الأصل المحلي.
4. في قاعدة جديدة فقط نفّذ إعداد الأدمن تفاعليًا وغيّر كلمة البداية عبر اتصال محلي محمي بنفق SSH. في قاعدة منقولة لا تعِد إنشاء الأدمن. الإنتاج يرفض كلمة البداية؛ لا تتجاوز الفحص.
5. راجع ملف `rihlati.service`، وافحصه بـ`systemd-analyze verify` قبل تثبيته. الخدمة تعمل خلف HTTPS، وتثق في وكيل محلي واحد فقط. لا تضف CDN دون مراجعة الثقة بعناوين المستخدمين.
6. راجع A وAAAA للاسمين `rihlati.me` و`www.rihlati.me` قبل تحويلهما للسيرفر المؤكد. لا تترك IPv6 يشير إلى الاستضافة السابقة. احتفظ بالقيم السابقة ولا تعدل سجلات البريد MX/TXT. عند النشر الأول فُصل ربط MyWebsite NOW بموافقة صاحب المشروع، بما فيه سجلّا TXT المخصصان لتلك الخدمة فقط؛ بقيت سجلات البريد كما هي.
7. ثبّت Caddy من مصدره الرسمي، وراجع `Caddyfile` ثم افحصه بـ`caddy validate --config /etc/caddy/Caddyfile`. لا تستبدل إعداد موقع آخر. تحقق من الشهادة وتحويل www قبل إتاحة تجربة التحكيم.
8. اختبر HTTPS والجلسات الآمنة والعزل بين المكاتب والمصادر والتذاكر، وتجربة `/app/` ومنع الأدمن فيها، وحجب الملفات الخاصة. اختبارات AI والصوت الحقيقية منفصلة عن الاختبارات المحلية الوهمية وتحتاج ميزانية خدمة.

OCR العربي الاختياري يحتاج Poppler (`pdftoppm`)، واعتماديات `Rihlati/package.json` وملف `data/ocr/lang/ara.traineddata`. نشر الواجهة لا يعني اكتمال OCR لكل اللغات؛ لا تعِد فهرسة المكتبة أثناء النقل تلقائيًا.

## النسخ الاحتياطي والرجوع

`rihlati-backup.service` و`rihlati-backup.timer` ينتجان لقطة SQLite يومية محلية فقط. جهّز المجلدات أولًا. لا يحذف المؤقت نسخًا قديمة؛ راقب القرص وحدد الاحتفاظ. اللقطة لا تشمل الكتب والصور والأسرار: تحتاج هذه نسخة منفصلة مشفرة خارج السيرفر واختبار استعادة. لا تنشر أي نسخة حسابات في GitHub.

قبل كل تحديث احتفظ بالكود السابق ونسخة بيانات متسقة. لا ترجع لكود قديم قبل التأكد من توافق ترحيلات البيانات، ولا تستبدل قاعدة حية وتفقد المعاملات الجديدة. DNS ليس رجوعًا فوريًا بسبب زمن الانتشار.

شغّل `python Rihlati/scripts/release_check.py` قبل الإضافة إلى Git وكرره مع `--staged` قبل commit، مع مراجعة يدوية. هذا فحص مبدئي وليس ضمانًا لغياب كل سر أو ثغرة.

المراجع: [تثبيت Caddy](https://caddyserver.com/docs/install)، [رؤوس الوكيل](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)، [خيارات Waitress](https://docs.pylonsproject.org/projects/waitress/en/stable/arguments.html).
